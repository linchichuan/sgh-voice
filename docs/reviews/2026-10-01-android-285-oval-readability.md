# Android 2.8.5：橢圓收音介面與閱讀整理

本輪以 Android 輸入法操作為主。versionCode 35；個人側載更新與 Google Play 封閉測試是不同交付管道。使用者已確認送出 2.8.4 Alpha 審查，本輪不更換該審查中的 bundle，也不宣稱 Google 已核准。

## 介面結果

| Before | After | Why |
|---|---|---|
| 上排 SGH 13sp | 最高 17sp、自動縮放至 14sp；原上排配置保留 | 提升品牌辨識，不擠壓語言切換入口 |
| 中央兩個較大的模式卡片 | 左右靠邊、中央留白；可視高度 28dp、觸控高度 44dp | 降低存在感，保留易點選的範圍 |
| 圓形與局部漸層 | 約九成鍵盤寬的橢圓；中心向邊緣漸淡、無外框 | 主視覺集中在收音區 |
| 波形局限於中間 | 橢圓內寬波形；真 PCM 進來才動，靜音平線 | 讓收音狀態可辨識且不製造假收音 |
| 底列語音按鍵較高 | 可視高度 32dp、觸控高度 48dp | 釋出視覺空間但保留手指操作容錯 |
| 波形／操作說明佔空間 | 移除下方說明；保留狀態、秒數與中央操作標示 | 減少閱讀負擔 |

語音、注音、日文、英文共用高度。App → 基本設定 → 鍵盤高度，可調 90–125%；短視窗仍提供中間區域捲動。手動鍵盤尺寸不因語音底列縮小而改變。

## 文字結果

- Claude、OpenAI、Groq 使用相同聽寫整理規則：補齊標點、話題轉折分段、清楚並列要求可條列；第一點、第二點等口述可轉為編號清單。
- 保留原順序、細節、專有詞、數字、日期、版本與否定。聽寫整理不代答問題、不新增事實、不附加 AI 前言。
- 修正條列編號被當成新增數字而誤拒絕的問題。只忽略從 1 開始、連續且至少兩項的新增行首編號；項目內金額、數量、版本、URL、路徑仍核對。來源已含編號時仍保護原順序。
- 若模型把原有句尾標點全部移除，拒絕該結果並保留原文。API 不可用／未啟用時仍依既有策略降級；沒有可用模型時不宣稱已完成智慧分段。
- 幫我寫的草稿也要求依話題短段落與清楚列點；仍由使用者確認後輸入。

## 手機仍待驗

1. 在常用聊天 App、記事本與瀏覽器欄位點選橢圓，開始／停止／處理中狀態直觀，沒有誤觸。
2. 90%、100%、125% 高度及慣用字體大小下，SGH、狀態秒數、中央文字與底列沒有裁切。
3. 說「第一點請檢查 GitHub Actions，第二點跑 CI/CD，第三點不要 git push」，確認條列、標點與否定完整插入。
4. 長口述更換話題，確認合理分段；短訊息保持自然短句，不強制清單。
5. 口述兩個不同金額、日期與版本，確認整理沒有調換或修改數值；API 失敗的提示與原文回退清楚。
